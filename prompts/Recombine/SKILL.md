---
name: recombine
description: recombine fuses components, primitives, mechanisms, or ontologies from multiple frameworks to generate novel hybrid models. unlike metaphorize (which maps one domain onto another) or diverge (which expands option space), recombine constructs **true cross-domain syntheses** with new structure. it searches for overlapping primitives, tension points, and emergent joints, producing frameworks neither parent domain contains alone.
---

## tl;dr

**recombine ≠ metaphorize.**

- **metaphorize** → map source → target  
- **recombine** → merge multiple sources into a new conceptual organism  

recombine asks:

> “if I splice these frameworks together at the structural level — not superficially — what hybrid model emerges?”

it’s a **fusion operator**, not a translation one.

---

## when to use

use **recombine** when you want:

- new hybrid **frameworks**  
- cross-domain **innovation**  
- unified models that explain more than any single input  
- ontological **bridges**  
- cross-disciplinary **mechanisms**  
- interfaces between fields (econ × bio, governance × ML, psych × systems)

don’t use when:

- you want analogies → **metaphorize**  
- you want alternatives → **diverge**  
- you want assumptions → **excavate**  
- you want causal trees → **backchain**  
- you want lived instantiation → **narrativize**

rule of thumb:  
**recombine = structured conceptual gene-splicing.**

---

## recombination types (menu)

### **primitive fusion**  
combine basic building blocks (states, agents, incentives, resources).

### **mechanism grafting**  
take a mechanism from one domain and graft it into another.

### **constraint overlaying**  
apply the constraints of one system onto another’s dynamics.

### **ontology blending**  
merge category systems and see what hybrid categories emerge.

### **dynamical merging**  
merge update rules, equilibria, learning dynamics, or feedback loops.

### **structural resonance**  
find isomorphic substructures and recombine them into a single model.

---

## signature

recombine(frameworks[], mode?, max_outputs?) → hybrids[]

- **frameworks[]:** 2–4 source domains or conceptual systems  
- **mode:** optional emphasis (mechanisms | primitives | constraints | ontology | dynamics)  
- **max_outputs:** default 3–6 distinct hybrids

output includes:

- **hybrid frameworks** (each 3–6 sentences)  
- **source-lineage** (what came from where)  
- **novel mechanisms** (what’s genuinely new)  
- **applicable regimes** (where the hybrid is useful)  

---

## process (step by step)

### step 0: extract source primitives  
for each framework:

- identify its key entities  
- mechanisms  
- constraints  
- incentives  
- typical dynamics  

### step 1: choose recombination axes  
select how the fusion happens:

- primitive → primitive  
- mechanism → mechanism  
- constraint → dynamic  
- process → process  
- ontology → ontology  

(or mix)

### step 2: generate candidate hybrids  
for each axis:

- create 1–3 fused frameworks  
- ensure hybrids differ in:  
  - primitives  
  - causal structure  
  - cost surface  
  - equilibrium logic  
  - failure modes  

### step 3: stress-test hybrids  
check for coherence:

- do primitives conflict?  
- do constraints invalidate mechanisms?  
- does the update rule make sense?  
- does the hybrid degenerate back into a parent system?  
- if incoherent, mark `[UNSTABLE]` or mutate until stable.

### step 4: highlight novelty  
for each hybrid:

- identify emergent properties  
- identify new explanatory power  
- identify new intervention levers  
- identify new failure modes

### step 5: specify regimes  
describe where the hybrid model is most applicable:

- high-load environments?  
- coordination problems?  
- noisy systems?  
- narrow domains?  
- long horizons?

## quality criteria

**structural novelty**  
- [ ] hybrid introduces new primitives or mechanisms  
- [ ] not a shallow analogy game  

**coherence**  
- [ ] doesn’t internally contradict itself  
- [ ] preserves internal logic of contributing pieces  

**orthogonality**  
- [ ] hybrids differ meaningfully from each other  
- [ ] not just rephrasing the same blend  

**applied usefulness**  
- [ ] each hybrid solves or illuminates something  
- [ ] has a clear regime where it beats a parent framework

## genre-specific patterns

### science / research  
blend two explanatory systems into a new mechanism (e.g., ecology × social networks).

### governance  
combine incentive structures with control-theory dynamics.

### strategy  
blend game theory with thermodynamics or attention economics.

### systems design  
cross-combine architectures (agent-based + market-based, rule-based + gradient-based).

### epistemics  
merge reasoning frameworks (bayesian + mechanistic + phenomenological).

---

## anti-patterns

- **portmanteau nonsense** — “cyber-ecological governance-body.”  
- **category paste** — sticking vocabularies together without structural fusion.  
- **framework tourism** — only superficial name-dropping.  
- **monolithic blend** — losing the texture of all component parts.  
- **overfitting** — creating a model that only works in contrived edge-cases.

---

## integration with other ops

**upstream:**  
- diverge → identify which frameworks to recombine  
- excavate → surface assumptions to fuse  
- backchain → select causal mechanisms to merge  

**downstream:**  
- narrativize → instantiate hybrid in a lived story  
- simulate → project hybrid under different regimes  
- attack → find hybrid failure modes  
- future_memory → see how hybrid plays out across time  
- prioritize → decide which hybrid to invest in

## examples (mini)

### example 1: recombine “game theory × thermodynamics × ecology”

**hybrid 1: energy-landscape game ecosystems**  
strategies are species occupying an energy landscape; payoffs equal free-energy gradients. equilibria behave like thermodynamic phases: high-entropy states create cooperative niches; low-entropy basins create competitive traps. ecological succession maps to shifts in accessible energetic basins.

**hybrid 2: entropic nash fields**  
agents minimize local “entropic regret.” nash equilibria correspond to metastable states in a dissipative system. perturbations behave like heat pulses that reorganize equilibria.

**hybrid 3: resource-flux evolution games**  
interactions follow conservation-like constraints. strategies consume and release abstract “resources,” producing gradient flows; stable attractors act like ecological climax communities.

---

### example 2: recombine “market design × cognitive psychology”

**hybrid 1: bounded-rational clearinghouses**  
matchmaking markets incorporate cognitive load into their utility functions; clearing rules penalize choice overload. equilibrium efficiency depends on attentional slack, not just supply-demand curves.

**hybrid 2: salience-weighted auctions**  
bids include not only value but perceived salience; auction dynamics shift when attention acts as a scarce tradable resource. classic efficiency theorems break; new failure modes appear.

**hybrid 3: motivational-quasi-market loops**  
agents trade not goods but intention-commitments. prices reflect motivational stability; arbitrage occurs when stated intentions diverge from behavioral likelihood.
